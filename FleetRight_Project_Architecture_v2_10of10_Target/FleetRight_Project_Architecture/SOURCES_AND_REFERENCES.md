# Sources and References

This file is an implementation reading list. External documentation informs semantics; all FleetRight performance claims must come from FleetRight's own reproducible experiments.

## Kubernetes autoscaling

Read the current Kubernetes documentation for:

- [Horizontal Pod Autoscaling](https://kubernetes.io/docs/concepts/workloads/autoscaling/horizontal-pod-autoscale/);
- [`autoscaling/v2` HPA API](https://kubernetes.io/docs/reference/kubernetes-api/autoscaling/horizontal-pod-autoscaler-v2/);
- scaling behavior and directional policies;
- downscale stabilization;
- tolerance/deadband;
- missing/not-ready metric handling;
- readiness/startup behavior.

FleetRight's HPA-like baseline should capture these important semantics rather than using a strawman threshold as the only reactive competitor.

## Kubernetes disruption and placement

Read current documentation for:

- [PodDisruptionBudget `policy/v1`](https://kubernetes.io/docs/reference/kubernetes-api/policy/pod-disruption-budget-v1/);
- [disruptions / eviction semantics](https://kubernetes.io/docs/concepts/workloads/pods/disruptions/);
- [topology spread constraints](https://kubernetes.io/docs/concepts/scheduling-eviction/topology-spread-constraints/);
- affinity/anti-affinity;
- taints/tolerations;
- pod readiness;
- node cordon/drain behavior.

FleetRight must not claim a live “pod move.” In the supported Kubernetes model, movement is an eviction/recreation/scheduling outcome.

## Prometheus latency measurement

Read current [Prometheus histogram and summary guidance](https://prometheus.io/docs/practices/histograms/).

Key rule for FleetRight:

- use aggregatable histogram distributions for fleet/service tail latency;
- do not average per-instance precomputed quantiles;
- retain count/sample evidence and choose buckets/resolution around relevant SLO thresholds.

## Predictive autoscaling

Review current [AWS Application Auto Scaling predictive scaling documentation](https://docs.aws.amazon.com/autoscaling/application/userguide/aas-predictive-scaling-how-it-works.html), especially:

- forecast-only evaluation;
- pre-launch/scheduling buffer;
- asymmetric behavior where forecasts can prepare scale-out while scale-in relies on real-time/dynamic evidence.

FleetRight uses the same safety intuition but implements its own local forecasting and verification model.
