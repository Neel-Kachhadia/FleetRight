## Safe behavior change

FleetRightWorkload reconciliation now retains nonterminal Pods whenever live
count exceeds desired count and reports `Reconciled=False` with
`ScaleDownRequiresStagedExecution`. `Ready` and `Available` report observed Pod
readiness and floor status; the new kubectl `Reconciled` column exposes the
blocked controller state. Availability-floor violations retain their specific
reason. Terminal Pod cleanup remains UID-preconditioned and has a direct API
request unit test.

New managed PDBs record a workload-generation high-water annotation. Unit tests
cover a lower-generation snapshot, a newer generation update, and the API
patch's resourceVersion and generation marker. An existing unmarked PDB now
fails closed without changing its budget: review showed that bootstrapping its
marker from a possibly stale workload snapshot could later loosen the budget.
These are local tests; older controller binaries ignore the marker, and no
trusted migration or mixed-version rollout is qualified.

V2 `MOVE_REPLICA` and `DEACTIVATE_NODE` remain rejected. `evict_one` and `cordon`
have no production call sites and are not execution-admitted. No V2 target-side
authority, durable eviction, node drain, or compensation was enabled.

PostgreSQL and Docker tests were not run. The recorded isolated DB credential
is unrotated, and the Docker socket is unavailable in this session.
